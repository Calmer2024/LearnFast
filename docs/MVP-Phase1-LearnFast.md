## 1. 第一阶段目标

第一阶段 MVP 的目标是打通 LearnFast 的本地个人学习闭环：

用户可以在本机创建学习空间，导入多类型资料，完成资料问答，保存笔记，生成和维护学习计划，确认和删除记忆，并手动生成学习报告。

MVP 不追求复杂协作和商业化能力，重点验证：

- 本地优先的学习空间是否可用。
- 多类型资料是否能稳定进入 Markdown 和索引管线。
- 带引用问答是否让用户信任答案。
- 笔记、计划、记忆和报告是否能形成学习闭环。
- 用户自带模型密钥是否能降低产品早期成本和配置复杂度。

## 2. MVP 决策快照

| 事项 | 第一阶段结论 |
| --- | --- |
| 运行形态 | 本地/单用户版本 |
| 技术栈 | React + Python |
| 模型使用 | 用户自带模型密钥 |
| 存储策略 | 本地优先 |
| 限制策略 | 文件大小、资料数量、空间数量先代码硬编码 |
| 复查形式 | 复习问答 + 计划任务 |
| 学习报告 | 用户手动生成 |
| 资料类型 | 文件 + 网页链接 + YouTube + EPub + CSV/Excel |
| 空间内一级入口 | 学习、资料、笔记、计划、记忆、报告 |

- 高质量扫描 PDF OCR 调优。
- 高级重排序模型接入。
- 资料批量标签和批量启停。
- 报告模板选择。

- 自动周期报告和通知。
- 公开课程市场、社区、内容售卖。

## 5. 关键用户流程

### 5.1 首次使用

1. 用户启动本地 LearnFast。
2. 进入学习空间首页。
3. 配置模型密钥并完成连接测试。
4. 创建第一个学习空间。
5. 上传资料或导入网页链接。
6. 等待资料转换和索引完成。
7. 在“学习”中提问。
8. 查看带引用回答。
9. 将回答保存为笔记。
10. 生成初始学习计划。

验收：

- 首次完成上述流程不需要账号。
- 应用重启后空间、资料、笔记、计划仍存在。
- 回答引用可以回跳到资料 Markdown 片段。

### 5.2 资料导入与问答

1. 用户进入某学习空间。
2. 在“资料”页上传文件或提交 URL。
3. 系统展示处理状态。
4. 资料 ready 后，用户在“学习”页选择资料范围。
5. 用户提问。
6. 系统执行增强检索并流式回答。
7. 用户查看引用、保存回答、反馈问题。

验收：

- 支持文件样例：PDF、DOCX、PPTX、MD、TXT、图片、音频、EPub、CSV、XLSX。
- 支持链接样例：普通网页、YouTube。
- 资料处理失败时可重试。
- 关闭某资料后，新回答不得引用该资料。

### 5.3 笔记与记忆

1. 用户创建 Markdown 笔记或保存 AI 回答为笔记。
2. 系统提取笔记摘要、标签和记忆候选。
3. 用户进入“记忆”页查看候选。
4. 用户确认、改写或忽略候选。
5. 长期记忆用于后续问答、计划和报告。

验收：

- 笔记可编辑、保存、删除。
- 记忆候选必须显示来源。
- 删除记忆后，新问答不再使用该记忆。

### 5.4 计划与复习

1. 用户在“计划”页输入目标、截止时间和每周学习时间。
2. AI 基于资料、笔记和记忆生成计划。
3. 用户手动调整任务。
4. 用户点击复习任务进入复习问答。
5. 完成后系统记录复习结果。

验收：

- 计划任务可新增、编辑、删除、完成。
- 复习任务必须说明推荐依据。
- 用户延期或未完成任务后，系统可以提出调整建议。

### 5.5 手动学习报告

1. 用户进入“报告”页。
2. 选择报告范围：本周、近 30 天、阶段报告。
3. 点击生成。
4. 系统基于学习记录生成报告。
5. 用户保存为笔记或导出 Markdown。

验收：

- 数据不足时报告明确说明不足。
- 报告包含完成事项、未完成事项、知识点、薄弱点、下一步建议。
- 关键结论能回溯到资料、笔记、问答、计划或记忆。

## 6. 功能拆分与验收标准

### MVP-01 本地应用骨架

交付：

- React + TypeScript + Vite 前端项目。
- Python + FastAPI 后端项目。
- 本地数据目录初始化。
- 开发启动脚本。
- 健康检查 API。

验收标准：

- 一条命令可以启动前后端开发环境。
- 打开本地地址后展示学习空间首页。
- `GET /api/health` 返回后端状态、数据目录状态和版本号。
- 首次启动自动创建本地数据目录和 SQLite 数据库。

### MVP-02 模型设置 BYOK

交付：

- 模型 provider 列表。
- API Key 输入和保存。
- 连接测试。
- 模型能力标签。
- 默认模型选择。

验收标准：

- 用户可以配置至少一个 LLM provider 并通过连接测试。
- 密钥不在 UI 中明文回显。
- 连接失败展示明确原因。
- 用户可以选择默认聊天模型和 embedding 模型。
- 模型设置页说明外部模型会接收哪些上下文。

### MVP-03 学习空间管理

交付：

- 空间列表。
- 创建空间。
- 进入空间。
- 重命名。
- 归档。
- 删除。

验收标准：

- 用户可创建最多 20 个空间。
- A 空间资料、笔记、计划、记忆不会出现在 B 空间默认视图。
- 删除空间前展示影响范围并二次确认。
- 归档空间不出现在默认列表，但可恢复。

### MVP-04 资料导入与转换

交付：

- 文件上传。
- URL/YouTube 导入。
- 资料处理任务。
- Markdown 转换预览。
- 资料状态管理。
- 资料启停和删除。

验收标准：

- 支持样例文件：PDF、DOCX、PPTX、MD、TXT、PNG/JPG、MP3/WAV、EPub、CSV、XLSX。
- 支持网页 URL 和 YouTube URL。
- 每个资料展示处理状态：待处理、转换中、索引中、可问答、失败。
- 转换后的 Markdown 可以预览。
- 用户停用资料后，新问答不再引用该资料。
- 资料失败后可以重试或删除。

### MVP-05 分块、索引与引用

交付：

- Markdown 结构化分块。
- chunk 元数据。
- embedding 生成。
- 本地向量库写入。
- 引用定位。

验收标准：

- chunk 保留标题路径、来源、位置和版本。
- 问答引用可以定位到具体资料片段。
- 删除资料后，对应向量不再参与新检索。
- 资料重新处理后使用最新版本 chunk。
- 应用重启后索引仍可用。

### MVP-06 学习问答

交付：

- 空间内聊天。
- 流式回答。
- 来源范围选择。
- MQE。
- HyDE。
- 引用展示。
- 保存回答为笔记。
- 回答反馈。

验收标准：

- 用户可对当前空间资料提问。
- 回答默认包含引用；无引用时说明原因。
- 用户选择资料范围后，回答只使用该范围。
- HyDE 生成内容不作为引用展示。
- 资料不足时不编造答案。
- 用户可一键保存回答为笔记。

### MVP-07 笔记

交付：

- Markdown 笔记列表。
- 创建、编辑、删除。
- 碎片笔记。
- 从回答保存笔记。
- 标签和搜索。
- 笔记进入索引。

验收标准：

- 笔记保存后刷新页面仍存在。
- 从回答保存笔记时保留原问题、回答和引用。
- 笔记可被当前空间搜索命中。
- 删除笔记前提示是否删除关联记忆。

### MVP-08 记忆

交付：

- 记忆候选列表。
- 长期记忆列表。
- 七层记忆分类。
- 来源展示。
- 确认、改写、忽略、删除。
- 自动提取开关。

验收标准：

- 对话和笔记可以生成记忆候选。
- 每条记忆展示来源和类型。
- 高影响记忆需要用户确认。
- 删除记忆后新问答不再使用。
- 关闭自动提取后不再生成新候选。

### MVP-09 学习计划与复习问答

交付：

- 创建计划。
- AI 生成计划。
- 任务列表。
- 任务编辑。
- 完成记录。
- 复习任务入口。
- 计划调整建议。

验收标准：

- 用户可以在没有资料时基于目标生成初始计划。
- 用户可以基于资料重新生成计划建议。
- AI 生成计划前展示关键假设。
- 任意任务都可手动编辑和完成。
- 复习任务可进入学习问答并记录结果。

### MVP-10 手动学习报告

交付：

- 报告生成入口。
- 报告范围选择。
- 报告 Markdown 输出。
- 保存为笔记。
- 导出 Markdown。

验收标准：

- 用户可手动生成当前空间报告。
- 报告包含完成事项、未完成事项、主要知识点、薄弱点、下一步建议。
- 关键结论带证据来源。
- 数据不足时不生成空泛报告。

### MVP-11 搜索与导出

交付：

- 空间内统一搜索。
- 笔记、计划、报告导出 Markdown。
- 学习空间基础导出。

验收标准：

- 搜索覆盖资料标题、Markdown chunk、笔记、记忆、计划任务。
- 搜索结果标明类型和来源。
- 用户可以导出笔记、计划、报告为 Markdown。
- 导出不包含模型密钥。

## 7. 硬编码限制

| --- | --- |
| 最大空间数 | 20 |

## 9. 验收 Demo 脚本

Demo 数据：

- 一个 PDF。
- 一个 DOCX。
- 一个 PPTX。
- 一个 Markdown。
- 一张图片。
- 一个音频。
- 一个 EPub。
- 一个 CSV。
- 一个 XLSX。
- 一个网页 URL。
- 一个 YouTube URL。

Demo 流程：

1. 启动本地应用。
2. 配置模型密钥并测试。
3. 创建“Python 数据分析学习”空间。
4. 上传和导入 Demo 数据。
5. 等待资料处理完成。
6. 在“学习”中提问：“这些资料中 Pandas 数据清洗的核心步骤是什么？”
7. 查看带引用回答。
8. 保存回答为笔记。
9. 创建一条碎片笔记：“我总是混淆 merge 和 concat。”
10. 查看记忆候选并确认一条薄弱点记忆。
11. 生成 2 周学习计划。
12. 完成一个复习问答任务。
13. 手动生成阶段报告。
14. 导出笔记、计划和报告。
15. 重启应用，确认数据仍存在。

通过标准：

- 全流程无账号。
- 回答引用准确。
- 空间数据本地持久化。
- 记忆可删除。
- 报告可保存为笔记。

## 10. 风险与收敛策略

| 风险 | 影响 | 收敛策略 |
| --- | --- | --- |
| MarkItDown 对复杂文件转换质量不稳定 | 资料问答质量下降 | 首阶段用样例集验收，失败展示可重试和原文预览 |
| 用户模型能力差异大 | 问答、嵌入、转写表现不一致 | 模型能力标签和连接测试必须先行 |
| YouTube 字幕不可用 | 视频资料无法转换 | 明确失败原因，允许用户上传字幕或音频文件 |
| 本地向量索引损坏 | 问答无法检索 | 支持按资料重新索引 |
| 引用定位不准 | 用户不信任答案 | chunk 必须保留 locator，回答后做引用校验 |
| 本地数据目录过大 | 用户磁盘压力 | 展示资料大小，提供删除资料和清理索引 |
| 记忆自动提取误判 | 个性化出错 | 高影响记忆必须用户确认，删除立即生效 |

## 11. 第一阶段完成定义

第一阶段 MVP 完成需要同时满足：
